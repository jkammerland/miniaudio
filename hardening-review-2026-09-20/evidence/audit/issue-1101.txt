#1101 Heap buffer overflow (read) in ma_dr_wav__strlen (miniaudio.h:80659) | closed | completed | 2026-09-18T11:51:59Z
https://github.com/mackron/miniaudio/issues/1101
Found via static analysis of the two-pass metadata allocator combined with targeted fuzzing (libFuzzer + AddressSanitizer) using a hand-crafted BEXT seed containing a non-null-terminated coding history field. Confirmed 2026-03-09. In line with the project's security policy favoring public and transparent handling, I am opening this issue to coordinate a fix.

**Affected version:** v0.11.25 (2026-03-04, latest)                                                                                                       
**Tested on:** Ubuntu 24.04, clang 18 

---

### Summary

When parsing a WAV file containing a `bext` (Broadcast Extension) chunk whose coding history field has no null terminator, `miniaudio.h` calls `ma_dr_wav__strlen()` on a heap buffer that was never null-terminated. The pool allocator uses `malloc()` (uninitialized memory), and the `+1` terminator slot is never written. `strlen` therefore reads past the end of the allocated pool - an unbounded **heap-buffer-overflow (OOB read)**.

---

### Affected code

**`miniaudio.h` lines 80803–80808 - `ma_dr_wav__read_bext_to_metadata_obj`:**

```c
extraBytes = (size_t)(chunkSize - MA_DR_WAV_BEXT_BYTES);
if (extraBytes > 0) {
    pMetadata->data.bext.pCodingHistory = (char*)ma_dr_wav__metadata_get_memory(pParser, extraBytes + 1, 1);
    MA_DR_WAV_ASSERT(pMetadata->data.bext.pCodingHistory != NULL);
    bytesRead += ma_dr_wav__metadata_parser_read(pParser, pMetadata->data.bext.pCodingHistory, extraBytes, NULL);
    pMetadata->data.bext.codingHistorySize = (ma_uint32)ma_dr_wav__strlen(pMetadata->data.bext.pCodingHistory);
    //                                                  ^^^^^^^^^^^^^^^^^ null terminator never written
}
```

**`miniaudio.h` line 80498 - pool allocator:**
```c
pParser->pData = (ma_uint8*)pAllocationCallbacks->onMalloc(ma_dr_wav__metadata_memory_capacity(pParser), pAllocationCallbacks->pUserData);
// malloc() — uninitialized memory, no calloc/memset
```

**`miniaudio.h` lines 80656–80663 - unbounded strlen:**
```c
MA_PRIVATE size_t ma_dr_wav__strlen(const char* str)
{
    size_t result = 0;
    while (*str++) {   // reads until null byte — no bounds check
        result += 1;
    }
    return result;
}
```

---

### Root cause

The Stage 2 BEXT reader:

1. Allocates `extraBytes + 1` bytes from the pool (the `+1` is intended as the null terminator slot).
2. Reads `extraBytes` bytes from the file into the buffer.
3. **Never writes `'\0'` at `pCodingHistory[extraBytes]`.**
4. Calls `ma_dr_wav__strlen(pCodingHistory)` — which scans forward until a null byte with no bound.

Because the pool comes from `malloc()`, the `+1` slot (and anything beyond the pool) is uninitialized. If no null byte is encountered in the remaining pool memory, `strlen` reads past the entire allocation.

The bug is not masked by debug assertions: the pool is exactly sized to hold all Stage 2 allocations, so no assertion fires before the `strlen` call. The OOB read occurs in both debug and release builds.

### Suggested fix

Write the null terminator after reading, and use the returned byte count directly (eliminates the unbounded `strlen` call entirely):

```c
if (extraBytes > 0) {
    size_t bytesJustRead;
    pMetadata->data.bext.pCodingHistory = (char*)ma_dr_wav__metadata_get_memory(pParser, extraBytes + 1, 1);
    MA_DR_WAV_ASSERT(pMetadata->data.bext.pCodingHistory != NULL);
    bytesJustRead = ma_dr_wav__metadata_parser_read(pParser, pMetadata->data.bext.pCodingHistory, extraBytes, NULL);
    pMetadata->data.bext.pCodingHistory[bytesJustRead] = '\0';  /* write null terminator */
    pMetadata->data.bext.codingHistorySize = (ma_uint32)bytesJustRead;
    bytesRead += bytesJustRead;
}
```

Alternatively, replace the `ma_dr_wav__strlen` call with the already-present `ma_dr_wav__strlen_clamped(pCodingHistory, extraBytes)`.

The fix looks like it landed on `dev` — the coding-history buffer is null-terminated there (`pCodingHistory[codingHistorySize] = '\0'`) — but the linked fix PR **#1115 was closed unmerged** (`merged: false`), and `master` / `0.11.25` still contain the original unbounded `ma_dr_wav__strlen` call at the same site. So the current release is still affected until `dev` is cut.

Minimal repro (opt-in metadata path, `MA_DR_WAV_WITH_METADATA`), miniaudio **0.11.25**:

A RIFF/WAVE with a valid PCM `fmt `, a `bext` chunk = the 602-byte fixed header **plus a non-empty coding-history field containing no NUL byte** (e.g. 64×`0x41`), and a `data` chunk; then:

    ma_dr_wav wav;
    ma_dr_wav_init_memory_with_metadata(&wav, buf, size, 0, NULL);   // -> OOB read
