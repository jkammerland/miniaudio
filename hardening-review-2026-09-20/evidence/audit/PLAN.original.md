**Minimal fixes and regression requirements**

1. **WAV bounds and progress: #1151/#1123 plus adjacent arithmetic.** Validate `fmt` minimum 16 bytes, extension-size field availability, and extension containment before any read or subtraction. Handle remaining size with checked unsigned arithmetic and forward-only, representable seeks; reject a pathological `fmt` remainder that cannot fit the parser's signed seek range. This keeps normal large data chunks separate from malformed huge format descriptions. Validate RIFF/RIFX fact >=4 and W64 fact >=8. Check W64 total chunk size >=24 at 80364, padding/addition overflow, AIFF COMM/SSND fixed-header subtraction at 81549/81581, and metadata read-count subtraction at 81637. For known-size streams, check chunk end against actual remaining bytes; for generic callbacks, preserve the seek/read contract and reject impossible sizes rather than relying on a logical cursor that can differ from actual progress. Keep valid large RF64/W64 files in the positive corpus. A broader resource/work budget, if required for unknown-length custom streams, must be explicitly designed rather than silently imposing a small arbitrary file-size limit.

   Tests: original #1151/#1123 fixtures through `ma_decode_memory`, `ma_decoder_init_memory`, file initialization and custom callbacks; undersized fmt/fact/SSND/W64 headers, oversized extensions, `INT_MAX`/`UINT32_MAX` boundaries, padding overflow, short reads, failed seeks, and decoder fallback. Include valid PCM, ADPCM, RIFX, RF64, W64 and AIFF boundary cases. Instrument seek/read counts with expectations based on fixture structure, not implementation-derived assertions. Error paths must release all decoder/metadata allocations. No API or public layout change expected.

2. **BEXT and metadata allocation: #1101/#1138.** At 80805–80808 reserve checked `extraBytes + 1`, read within that reservation, and terminate at the actual count before any string use. Preserve the historical first-NUL interpretation of `codingHistorySize` with a bounded scan; document any intentional change to byte-count semantics instead of adopting it accidentally. Reject truncated required metadata. For SMPL, compute loop bytes with checked multiplication, require them to fit after the 36-byte header, then require sampler-specific data to fit the remaining chunk. Share this validation between count and read passes. Replace assertion-only assumptions with error propagation for untrusted sizes; retain assertions for internal invariants. Check cumulative metadata allocation, alignment, `uint64_t` to `size_t` conversions, and allocation failure at 80467–80498. Do not introduce a blanket 64-MiB production cap.

   Tests: no NUL, first/embedded/final NUL, empty history, partial history read, truncated BEXT header, allocator failure at each stage, SMPL zero/multiple loops with valid nonempty sampler data, inconsistent counts/lengths, repeated metadata chunks, 32-bit size boundaries and exact allocation telemetry. A legitimate sampler payload must not be rejected by the old `(chunk-36)/24 == loopCount` heuristic. Default metadata-disabled decoding remains covered. No public layout change expected; malformed metadata that previously appeared accepted may now fail.

3. **Resource-manager ownership: #1141 and asynchronous retirement.** Cache only valid cleanup/ownership state before freeing the failed node; track notification initialization explicitly, free/remove exactly once, clear the local/output node pointer, and balance init/done fences on every failure. Merely swapping boolean operands or suppressing an assertion is insufficient. Audit early returns separately from the shared `done` path.

   Independently, `ma_resource_manager_data_buffer_node_unacquire` at 71033 and `ma_resource_manager_data_buffer_uninit` at 71337 equate a successful load result with complete job retirement. Development code adds retirement waits because jobs can still access state after publishing success. These are source-supported concurrency risks, not a fresh local UAF reproduction in this investigation. First force the publish/retire interleaving with deterministic barriers; fix only a confirmed failing interleaving. Respect `executionCounter/executionPointer` ordering, configured worker ownership, and manual job pumping. Do not insert a self-deadlocking wait when the current thread owns the work needed to retire the job.

   Tests: nonexistent/corrupt files, injected VFS read/seek failure, allocation failure, queue-full failure, synchronous, ASYNC and ASYNC|WAIT_INIT loads, existing/shared nodes and externally registered data. Verify exact close/free counts, null output on failure, balanced fences and no completion after operation retirement. Add load-versus-uninit and paged-load-versus-node-release barrier tests under ASan/TSan. Do not call uninit on an object whose initialization contract says it never initialized. Public ABI unchanged; uninit remains control-thread work and may wait.

4. **MP3 bounds: #1128/#1117.** Work in integer offsets relative to a validated frame/data extent; verify `offset <= length` before `required <= length-offset` and only then form pointers. Check the tag signature/flags, frame count, byte count, 100-byte TOC, quality and encoder-delay/padding fields independently. Do not assume allocation capacity equals initialized file data. Reproduce #1117 before widening the frame-count multiplication at 94974; widening does not make a hostile count trustworthy for allocation.

   Tests: 35-byte fixture, every truncation boundary for each optional tag field, memory and callback/file routes, valid CBR/VBR/Info/Xing/LAME files, malformed flag combinations and large count values. Assert initialized outputs only on success; unsupported optional metadata must not produce out-of-bounds reads or unbounded work. Run ASan/UBSan. No public ABI change expected.

5. **Gain smoothing and EOF: #1153-related defects/#1125.** Correct remaining-ramp length (`smoothTime - t`), clamp progression to the target, advance two-frame SIMD/MSVC unrolled iterations by two frames, carry the correct running value into an odd tail, and advance output/input pointers by frames * channels at 50902. The pointer correction becomes necessary once a single call correctly transitions from interpolation to constant gain. Make all changes together with independent mathematical expectations.

   For example, an eight-frame fade from 1 to 0 should produce `1, .875, .75, .625, .5, .375, .25, .125, 0...`. This checkout produces negative gains after frame 8 on scalar paths; stereo SSE2 produces `1, .875, .875, .75, .75, .625, 1` for a seven-frame block. Scalar mode removes the SIMD error but leaves duration overshoot, so disabling SIMD is not a fix.

   Tests: zero/one/odd/even block lengths, split-versus-single-block equivalence, ramps shorter/longer than a callback, changing targets mid-ramp, rising/falling gains, channels 1/2/6/8 and >32, in-place/out-of-place buffers and null-buffer time advancement. Then render controlled listener rotation offline and run the supplied Windows listening scenario; measure discontinuities without widening tolerances to accommodate bugs.

Do not claim a lower-level read contract permits arbitrary partial-data-plus-error combinations; test that contract explicitly. Test s16/f32 and other conversions, sounds shorter/equal/longer than cache/period boundaries, empty/one-frame sources, looping, exact tail samples, end notification once, and resampler tails where applicable. No public API/layout change; corrected samples will intentionally differ from broken output.

Microsoft's [IMMNotificationClient contract](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nn-mmdeviceapi-immnotificationclient) requires nonblocking callbacks and prohibits waits and certain registration/final-release operations there.

It must not retain borrowed device-ID pointers. The worker owns reroute, COM lifetime transitions, stop/start serialization and user notification delivery. Failed reinit leaves a coherent stopped/detached state and never calls a null audio client. Unregister/quiesce callbacks, stop accepting work, join/drain the worker, and release sidecar state before the public device disappears. **Real-time and Steam Audio constraints**

There is no evidence that the entire miniaudio engine is hard real-time safe under arbitrary public API calls. `ma_atomic_vec3f_set/get` at 51562/51571 take spinlocks, so concurrent listener updates can stall mixing if a writer is preempted. Node detach at 73994 waits for reader/reference counters around 74052–74057. Resource-manager stream jobs and decoding can allocate or access VFS; uninit waits. Sound end callbacks are invoked on the audio thread, and their contract at 11228 forbids operations such as restart/uninit/state changes from that callback. ASYNC|WAIT_INIT sound initialization at 78500 can block, and initialization notifications can fire before the caller finishes initializing its own state.

The miniaudio Steam Audio example is an example, not the real consumer: [engine_steamaudio.c](/mnt/d2/agent-workspace/repos/miniaudio/examples/engine_steamaudio.c:62). Its ordinary `direction` floats are written at 260–262 from the main loop and read at 105–107 by the audio callback without synchronization: a source-confirmed C data race. It uses nearest HRTF interpolation at 108. Valve documents that [nearest interpolation can switch audibly while moving, whereas bilinear interpolation is smoother](https://valvesoftware.github.io/steam-audio/doc/capi/guide.html). That is a separate potential contributor from #1153, whose attachment uses miniaudio spatialization without Steam Audio.

The example's processing at 115–146 also assumes fixed DSP blocks and needs a frame adapter/tail audit when fewer input frames arrive. SDK buffers/effects are allocated in initialization, but this does not establish allocation-free SDK processing on every supported version. [HRTF creation](https://valvesoftware.github.io/steam-audio/doc/capi/hrtf.html) is expensive and belongs off the audio thread; [binaural effects](https://valvesoftware.github.io/steam-audio/doc/capi/binaural-effect.html) have persistent state and tails. Validate positive block size before allocation and preallocate any required partial-block storage.

Proposed boundary for the backend and future consumer:

- Device lifecycle and scene/simulation/HRTF construction stay on control/worker threads. DSP effects have one processing owner; their lifetime spans all callbacks that can see them.
- Parameter updates use bounded preallocated snapshots/mailboxes, adopted at a block boundary. Old objects are reclaimed off the audio thread after acknowledgment. Do not replace the race with a mutex, an unbounded retrying seqlock, or an atomic shared_ptr whose last release can destroy objects in the callback.
- Choose a controlled mixer path: preload/convert assets or use bounded streaming queues, avoid concurrent listener setters against spinlocked getters, and schedule graph mutation/uninit after callback quiescence. Where uncontended internal locks remain, document the single-owner guarantee rather than declaring all library APIs lock-free.
- Audit the actual enabled callback path with allocation and lock instrumentation, worst-case block/voice counts, and state-update stress. Timing measurements inform a budget; they cannot prove a universal hard real-time guarantee. Queue overflow has a defined bounded policy and never loses an operation's only terminal completion.
- Keep example corrections separate from core WASAPI and parser commits. Native Steam Audio build/run validation is required before claiming the example or future integration is fixed. No Steam Audio integration is to be invented inside `timer_wheels`.

**Coroutine, cancellation and shutdown contract**

References: [resume_token](/home/ai-dev1/repos/timer_wheels/include/timer_wheels/timer_coro.h:466), [completion_token and contract](/home/ai-dev1/repos/timer_wheels/include/timer_wheels/timer_coro.h:802), [event-loop operations](/home/ai-dev1/repos/timer_wheels/docs/event-loop-ops.md), [async interoperability tests](/home/ai-dev1/repos/timer_wheels/tests/test_coro_async_interop.cpp).

`task`/`weak_task` use generation-checked weak completion by default; `keepalive_task` keeps the frame alive through strong tokens. `try_complete` claims the generation, pins the frame, runs its nothrow receiver, and resumes inline on the invoking thread. Neither token form posts to an event loop. Copies compete for one generation; mint one token per suspension and copy it, because minting another invalidates the first. Parent continuations can also run inline. Frame pinning does not keep the audio device, buffers, operation state or event loop alive; the last strong release can destroy a frame on that thread. `make_completion_token` currently accepts the default erased `resume_token`, so do not assume every policy-specific token is interchangeable with it.

The scheduler-owned raw callback optimization is limited to its single-threaded timer cancellation/lifetime contract. It is not permission to retain raw coroutine handles in external audio callbacks. Affine tokens are not cross-thread tokens. Manual `task::resume()` must not race a token path.

The future integration must allocate stable operation state before submitting work, including paths that complete synchronously during initialization. Store result/terminal state in that operation, not only in an awaiter's frame. Audio/backend callbacks publish bounded POD records or operation IDs to preallocated storage. A non-real-time dispatcher may then call the owning loop's `post`; the example loop at [example_7.cpp:17](/home/ai-dev1/repos/timer_wheels/examples/example_7.cpp:17) uses a mutex and deque and is not a real-time posting primitive. Invoke `completion_token`/`try_complete` only during the owning loop's ready phase when the contract requires loop affinity. Do not access the awaiter after publishing a completion that can cause it to be destroyed.

Cancellation has two obligations: claim an operation's terminal state once, and retire the external source before releasing its callback userdata. A stale resume token only suppresses frame access; it does not cancel an OS callback or make operation storage safe to free. Late/duplicate completion must release its payload even when the generation is stale. Keepalive tokens are an explicit retention policy with shutdown/cycle risks, not a blanket UAF fix.
