#1128 Heap-buffer-over-read (OOB Read) in ma_dr_mp3_init_internal due to missing input size validation for truncated metadata | closed | completed | 2026-05-29T21:54:35Z
https://github.com/mackron/miniaudio/issues/1128
Description:
A heap-buffer-overflow (READ of size 1) was discovered in miniaudio.h during fuzzing. The issue exists within the integrated dr_mp3 decoding module when parsing truncated MP3 frames containing Xing/Info metadata headers.

Vulnerability Mechanism:
Inside ma_dr_mp3_init_internal, the parser attempts to read the Xing or Info metadata header from the first frame data (pFirstFrameData). The code calculates the start position of the tag (pTagData) using the bitstream position:

C
pTagData = pFirstFrameData + MA_DR_MP3_HDR_SIZE + (bs.pos/8);

However, the parser evaluates the condition pTagData[0] == 'X' (or 'I') directly without verifying whether pTagData is still within the boundaries of the allocated frame buffer size. If an application parses a highly truncated input stream (e.g., a file containing only a partial frame of ~35 bytes), pTagData points beyond the allocated heap region, triggering an out-of-bounds read.

Impact:
An attacker-controlled truncated MP3 file can cause any application using miniaudio to crash immediately (Denial of Service) due to memory access violation.
